核心能力

从提问到看板的全链路，每一环都有确定性的工程兜底

Plan-first 思路确认

新问题先探查表结构、小样本验证，输出思路确认卡再执行——先对齐口径，再烧 token。

多数据源编排

关系型数据库（PostgreSQL / MySQL / SQLite / ClickHouse）+ 任意 MCP 数据源 + 本地文件（CSV·Excel → DuckDB），统一工具装配，跨源联合分析。

只读双保险守卫

SQL 词法守卫（仅 SELECT/WITH、禁多语句 DDL/DML、自动 LIMIT 200）+ 方言引擎级只读事务，双保险缺一不可。

断线重连 StreamHub

切会话、刷新页面不杀任务：服务端后台续跑、分块缓冲、秒级重放续接，回切输出不断线。

活看板零 LLM 刷新

收藏看板捕获取数查询，一键刷新按确定性变换重放回填——不走模型往返，贵与漂移都不存在。

上下文治理

存储层保存完整会话，压缩只作用于发往模型的投影：tool 结果剪枝 + LLM 摘要，长会话不爆窗、不丢史。

运行时防线

LLM 不可信是前提：预算、并发、截断、熔断、不变量，全部服务端强制

任务看门狗
wall-clock 超限自动中止，provider 挂起不占用
token 预算熔断
单任务累计超限即终态中止，成本敞口有界
并发准入
running 任务数超上限直接 429，重连不占名额
工具结果截断
超长结果信封化 + 「数据非指令」注入防御
重复循环熔断
生成退化自动截断并停止计费，合法内容保留

结构化遥测事件流（NDJSON，可注入 OTel）· finish_task 服务端不变量 · 双层 eval 体系

60 秒本地跑起来

克隆仓库，装依赖，起服务——打开 localhost:3006， 在「设置」里填入 OpenAI 兼容 API Key（或环境变量预置），即可开始提问。

想定制分析套路？把方法卡放进 data/methodology/*.json， 推荐列表与提示词注入同步生效，坏卡跳过不阻塞。
